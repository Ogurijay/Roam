# Roam

一套键鼠，控制多台电脑。在面前的直接切屏（A 模式），不在身边的远程看画面（B 模式）。
跨网络 P2P 直连、低延迟、开源。优先支持 Windows ↔ macOS。

设计见 [docs/design.md](docs/design.md)。

## 安装

从 [Releases](https://github.com/Ogurijay/Roam/releases) 下载：

- Mac：`roam-macos-universal`（Apple 芯片和 Intel 通用）
- Windows：`roam-windows-x86_64.exe`

装好之后，以后的新版本都可以在应用内一键更新（见下文）。也可以从源码构建：

```bash
cargo build --release
```

## 使用

每台电脑装同一个 Roam，打开后在窗口顶部选择角色（和 Deskflow 一样）：

- **用本机的键盘和鼠标控制其他电脑**（主机）
- **被其他电脑控制**（被控端）

Mac 和 Windows 都可以当主机，也都可以被控。程序常驻在托盘 / 菜单栏，点击图标打开窗口，关闭窗口只是缩回托盘。

**添加设备（在主机上）**

1. 同一局域网里打开了 Roam 被控端的电脑，会出现在「设备」页右侧的「附近的设备」，点「添加」；跨网络时在被控端窗口里「复制连接码」，粘贴到主机上
2. 被控端会弹出确认窗口，核对窗口里的校验码和主机上显示的一致后点「是」
3. 在 5×3 的网格里把电脑拖到对应位置：左右上下相邻的电脑之间，光标可以从那一边直接穿过去

首次运行时 macOS 需要在 **系统设置 → 隐私与安全性** 授权：主机需要「辅助功能」和「输入监控」，被控端需要「辅助功能」。
被控端固定使用 UDP 端口 47700（被占用时自动换成随机端口）。

### 切屏

- 快捷键（默认组合 `Ctrl + Option + Cmd`，可在页面里改）：
  - 组合 + `Esc`：强制回到 Mac
  - 组合 + `1~9`：直接切到对应编号的设备（回到上次离开的位置）
  - 组合 + `L`：锁定 / 解锁当前屏幕
- 「切屏」页可以调：直接切 / 停留后切 / 撞两下才切、需要按住的修饰键、角落死区；跨屏位置沿边按比例对应
- 点击某台设备可以单独设置：名称、启用 / 停用、指针速度、滚轮速度、纵向 / 横向滚轮反转
- 菜单栏或页面顶部可以「暂停切屏」「锁定当前屏幕」
- Mac 和 Windows 互控时默认 Cmd ↔ Ctrl 对调（双向），可以在「切屏」页关掉
- 拖拽（按住鼠标键）时不会切屏
- 切入仍在线但已熄屏的设备时，会请求系统点亮屏幕，再继续接收键鼠输入；需要被控端也运行包含此功能的版本。锁屏时仍需正常解锁，整机睡眠时需先唤醒电脑。

### 输入设置

「输入设置」页对主机和被控端都开放。Mac 菜单栏只显示固定图标，控制其他设备时不会追加动态文字；连接与控制状态仍可在菜单和页面中查看。

- **Mac 滚动**：鼠标滚轮、触摸板分别选择是否相对系统方向反转，默认均不反转。设置影响本机物理输入，包括转发到其他设备的滚动；接收到的 Roam 滚动不会再次反转。按 macOS 的离散/连续滚动事件分组，Magic Mouse 等连续滚动鼠标归入触摸板组。
- **键盘映射**：Mac → Windows、Windows → Mac 分开设置，仅影响跨设备控制，本机打字保持系统行为。可选 Cmd/Ctrl 互换预设、保持键位，或添加逐键规则。未指定的按键沿用「切屏」页的 Cmd/Ctrl 设置；同一来源键只允许一条规则，规则不连锁转换。接收方启用自定义时优先采用接收方规则；被控端修改后会同步给主机，主机需要 v0.3.4 或更新版本。
- 按 MacBook 常见布局提供按键，包括 Fn+Delete、Fn+方向键产生的导航键；独立 Fn/Globe、Touch ID 和亮度/媒体功能键暂不支持映射。Roam 切屏快捷键按原始按键识别；修改映射时会先返回主机并释放远端按键。

### 剪贴板与文件

也可以直接从文件管理器右键发送，不需要先复制或切换控制电脑。在 Roam 的「发送文件」页点击「添加右键菜单」（只安装到当前用户，无需管理员权限）：

- macOS：Finder 选中文件或文件夹 → 右键 →「Roam - 发送到其他电脑」（部分系统版本在「快速操作」或「服务」中）
- Windows：资源管理器选中文件或文件夹 → 右键 → 发送到 →「Roam - 发送到其他电脑」。Windows 11 可能需要先点「显示更多选项」

支持多选；在打开的窗口中选择在线电脑，再点击发送。接收端保存到「下载/Roam」，重名时另存，接收确认后才报告成功。主动发送不会改写剪贴板；被控端之间的文件通过主机临时转发，转发完成后清理临时副本。双方与主机均需要 v0.3.3 或更新版本，本机 Roam 须已运行。菜单只需在发送方安装，可在同一页面移除。

命令行也可以使用 `roam send -- 文件或文件夹 ...`；安装/移除菜单用 `roam context-menu install` / `roam context-menu uninstall`。自定义配置目录或界面端口时，沿用运行中的 Roam 的 `--config-dir` / `--ui-port` 参数。仅支持发送普通文件和文件夹，不跟随符号链接。

- 在一台电脑上复制，切到另一台直接粘贴，双向都可以：文本、富文本、图片（没有文字时）
- **复制文件或文件夹**后切屏，文件**不会**马上传；到另一台电脑上按粘贴（Windows 上 Ctrl+V，Mac 上 Cmd+V）时才传过去，放在对方的「下载/Roam」文件夹。5 秒内传完会自动替你粘贴，更大的文件传完后会提醒你再按一次粘贴；进度显示在布局页面和托盘里
  - 只有在那台电脑上没再复制过别的东西时才会拦下粘贴去取文件，复制了别的就照常粘贴
  - 用鼠标右键菜单里的「粘贴」不会触发传输，要用快捷键
- 可以分别设置大小上限，也可以按设备关闭

### 更新

- 主机和被控端每 6 小时检查一次新版本，菜单栏和页面会提示，也可以手动「检查更新」
- 被控端在「更新」页或菜单栏选择「更新本机并重启」，可直接从 GitHub 下载、校验和安装，不依赖主机在线；只更新本机，保留配置和授权，重启后等待主机自动重连。下载失败、校验或签名不通过时保留原程序，可重试。使用旧版被控端时，需要先升级到含此入口的版本。
- 点「更新所有设备」：主机下载各平台安装包（校验 SHA256），先推送给所有被控端，再更新自己，各设备自动重启，几秒后重新连上
- 主机已是最新版时仍可点「同步其他设备」，把旧版被控端补齐；不会降级较新的设备
- 更新连接使用最新发现的设备地址，独立于键鼠控制连接。每台设备的更新结果会保留，主机重启后仍可在「更新」页查看
- Mac 更新前会准备完整的新程序、检查签名再替换，写入或签名检查失败会保留原程序
- 被控端只接受已授权主机推送的更新
- 版本不一致的设备（比如更新时离线）会在设备列表里显示「同步版本」
- 从 GitHub 下载慢时，可以在页面里填一个下载镜像前缀

> macOS 上如果是让 roam 开机自启（而不是从终端运行），更新后系统可能要求重新授予「辅助功能」权限。从终端运行时权限属于终端，不受影响。

### 其他

- 只想在终端里运行、不要托盘和窗口：加 `--no-tray`；开机自启时不弹窗口：`--background`
- 「日志」页可以看运行日志，日志文件在配置目录的 `logs/roam.log`，程序崩溃时也会记录原因

### 控制偶尔失灵

主机每 250 毫秒给被控端发一次心跳，两边都会把异常写进日志：

- `「xxx」1 秒没有响应` / `恢复响应，中断了 N 秒`：网络中断，后面括号里是当时所有连接路径、延迟和累计丢包（`*` 是正在用的那条）。超过 3 秒没有响应时，主机会把光标收回本机，被控端会松开所有按键，对方恢复后自动放开
- `心跳定时器晚了 N 秒`：问题出在本机进程，被系统节流或者卡住了，不是网络
- `连接路径：中继`：局域网直连断了 15 秒以上才会退到中继，中继服务器在海外，延迟可能有几百毫秒

Roam 启动时会关闭 macOS 的 App Nap 和 Windows 的后台节能；光标在别的电脑上时，还会定期告诉本机系统"用户仍在操作"，避免本机息屏或睡眠。用 Wi‑Fi 的电脑出问题更多，能插网线就插网线。

### 光标移到某个程序上就控制不了（Windows）

那个程序是以管理员身份运行的。Windows 不允许普通程序向管理员窗口输入键鼠，日志里会出现 `「xxx」以管理员身份运行`。两种办法：

- 取消它的「以管理员身份运行」：右键程序 → 属性 → 兼容性，取消勾选
- 被控端「锁屏控制」启用后，打开「允许控制以管理员身份运行的程序」（需要管理员确认一次），之后由系统服务代为输入。代价是本机的恶意程序如果劫持了 Roam，也能借此操作管理员窗口；UAC 确认弹窗仍然不能控制

### 连通性测试

`roam-probe` 用来实测两台机器之间能不能直连、走哪条路径、延迟和丢包是多少：

```bash
roam-probe listen                 # 被测机器
roam-probe connect roam1xxxx...   # 另一台机器
```

## 发布新版本

1. 修改 `Cargo.toml` 里的 `version`，提交
2. 打标签并推送，GitHub Actions 会自动构建两个平台的安装包并发布：

```bash
git tag v0.2.0 && git push origin v0.2.0
```
